# Настройка opencode

Исполнитель — это opencode с ограниченными правами и тремя специализированными агентами.
Здесь — как его авторизовать, какую модель выбрать и как настроить границы под свой стек.

## Установка и авторизация

```bash
curl -fsSL https://opencode.ai/install | bash   # или см. https://opencode.ai
opencode --version                              # нужна 1.18+
```

```bash
opencode auth login        # синоним: opencode providers login
opencode auth list         # должно показать больше 0 credentials
```

Без авторизации `delegate.sh` работает только в режиме `--dry-run`, а `doctor.sh`
показывает `opencode has no credentials`.

## Бесплатные модели

Список доступных моделей меняется — смотрите актуальный своей командой:

```bash
opencode models
```

На момент написания без подписки доступны модели провайдера **opencode Zen**
(`opencode/…`): `big-pickle`, `deepseek-v4-flash-free`, `hy3-free`, `laguna-s-2.1-free`,
`mimo-v2.5-free`, `nemotron-3-ultra-free`, `nemotron-3.5-lightning-free`.

Модель задаётся в трёх местах, по возрастанию приоритета:

1. `.opencode/agents/implementer.md` — дефолт агента;
2. поле `model:` в карточке задачи — под конкретную задачу;
3. флаг `--model` у `delegate.sh` — разово.

```bash
bash scripts/delegate.sh T-003 --model opencode/nemotron-3-ultra-free
```

### Как выбирать

Начните с одной модели и меняйте по результатам ревью, а не по описаниям. Реальный
критерий один: сколько карточек проходят ревью с первой попытки.

Модель по умолчанию для всего проекта записывается на онбординге в `docs/constitution.md`:

```
executor-model: opencode/grok-code
```

Оттуда её берёт лид, когда в карточке не указано своё поле `model:`. Поменять — одна
строка в конституции, перезапускать ничего не нужно.

Практическое правило: механические задачи (добавить метод по подробной инструкции,
покрыть тестами) — самая быстрая модель; задачи, где надо связать несколько файлов —
модель посильнее. Если сильная модель тоже не тянет — проблема в карточке, а не в модели
(см. [Карточки задач](task-cards.md)).

### Приватность

У части бесплатных моделей провайдер оставляет за собой право использовать данные для
обучения — это указано в описании конкретной модели. Если код чувствительный, читайте
условия по своей модели или используйте платный провайдер / локальную модель. Процесс
от этого не меняется: `model:` в карточке может указывать на что угодно, включая
локальный Ollama или ваш ключ к любому провайдеру.

## Другие провайдеры

`opencode auth login` поддерживает много провайдеров. Всё, что от них требуется, —
уметь работать инструментами (tool calling). Ставите модель в поле `model:` карточки —
и процесс работает без изменений.

Дополнительные ключи и переопределения — через `provider` в `opencode.json`:

```json
{
  "provider": {
    "anthropic": { "options": { "apiKey": "{env:ANTHROPIC_API_KEY}" } }
  }
}
```

## Как устроены права

`opencode.json` в корне проекта. Ключевая часть — `permission`, карта
`шаблон → allow | ask | deny`. Более специфичный шаблон побеждает общий.

```json
"permission": {
  "edit": {
    "*": "allow",
    "docs/**": "deny",
    "docs/specs/*/reports/**": "allow"
  },
  "bash": { "*": "ask", "git push*": "deny", "npm test*": "allow" },
  "webfetch": "deny",
  "websearch": "deny"
}
```

Проверить, что правила действительно применились к агенту:

```bash
opencode agent list | sed -n '/^implementer (/,/^test-writer (/p' | grep -B1 -A1 'docs/\*\*'
```

Должно быть `"action": "deny"`.

### Подгонка под свой стек

В `bash` из коробки разрешены команды популярных экосистем (npm, pnpm, pytest, cargo,
go, make) и запрещены установки пакетов и все изменяющие команды git. Уберите лишнее и
добавьте своё:

```json
"bash": {
  "*": "ask",
  "./gradlew test*": "allow",
  "./gradlew build*": "allow",
  "mvn *": "deny"
}
```

Правило: **разрешайте только то, что нужно для `verify` и гейтов**. Всё остальное
пусть спрашивает — `ask` по умолчанию для `*` как раз для этого.

Не убирайте `deny` с установки пакетов и git — на них держится разделение ролей.

### Флаг `--auto`

`delegate.sh --auto` добавляет к запуску `opencode run --auto`: правки применяются без
вопросов. Правила `deny` при этом **продолжают действовать** — за `allowed_paths`,
в `docs/` и в git исполнитель всё равно не попадёт.

Когда делегирование запускает лид (то есть на `autonomy: supervised` и `auto`), `--auto`
**обязателен**. Без него `opencode run` встаёт и ждёт подтверждения каждой правки от
человека, которого в этой сессии нет, и запуск висит до тех пор, пока его не убьют.
`delegate.sh` отказывается стартовать без TTY и без `--auto`, вместо того чтобы зависнуть
молча.

Когда команду запускаете вы (`autonomy: manual`), `--auto` наоборот не нужен: смысл этого
режима — посмотреть, что модель вообще пытается делать. При `manual` скрипт не примет
`--auto` без `--force`.

## Агенты

`.opencode/agents/`:

| Агент | mode | Может писать | Для чего |
| --- | --- | --- | --- |
| `implementer` | primary | код по `allowed_paths` + отчёт | обычная реализация |
| `fixer` | primary | то же | доработка по findings ревью |
| `test-writer` | all | только тестовые пути + отчёт | задачи «покрыть тестами» |

Свои права агента складываются с глобальными из `opencode.json`; у `test-writer` они
строже — прод-код он изменить не может.

Проверить, что все трое подхватились:

```bash
opencode agent list | grep -E '^(implementer|fixer|test-writer) '
```

Встроенные агенты opencode (`build`, `plan`, `general`) остаются доступны и подчиняются
глобальным правам, но не знают про дисциплину карточек. Как их отключить — см.
[Роли](roles.md).

## Проверка настройки

```bash
bash scripts/doctor.sh
```

Проверяет: установлен ли opencode, есть ли credentials, git-репозиторий, все ли файлы
на месте, валиден ли JSON, действительно ли закрыт доступ к `docs/`, `CLAUDE.md`
и `.claude/`, загрузились ли три агента и заполнены ли гейты в конституции.
