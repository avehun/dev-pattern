# Если что-то не работает

## Claude не видит правил и индекса

- Запускали ли `/dev-pattern:setup` в этом репозитории? Без `docs/dp/knowledge/INDEX.md`
  хуки молчат намеренно.
- После `setup` нужна **новая** сессия: хуки и настройки читаются при старте.
- Не выключен ли плагин для проекта: есть ли `.git/dp/disabled` (его оставляет `dp-uninstall`
  без `--purge-kb`)? Снова включить: `/dev-pattern:setup`.
- Установлен ли `jq`? Без него хуки тихо пропускают работу (fail-open).
- `claude --debug` показывает, какие хуки запускались и что вернули.

## Stop-хук не даёт закончить

Так и задумано: за сессию изменился код, а документация нет. Варианты:
- обновить документы и модули базы знаний, которые описывают тронутый код (`dp-kb-stale`
  подскажет, какие);
- если документация правда не нужна: `dp-docs-waive "причина"`. Отказ действует только для
  текущего состояния файлов.

Если Claude три раза подряд не разобрался, хук отпускает ход и предупреждает тебя.

Ложные срабатывания на сгенерированных файлах: списки исключений лежат в начале
`plugins/dev-pattern/scripts/stop-docs.sh`.

## Plan mode мешает

Plan mode не мешает отвечать на вопросы, он только не даёт править файлы до одобрения плана.
Если для какого-то проекта это лишнее, поменяй `permissions.defaultMode` в настройках
проекта: `dp-uninstall` потом не тронет ключ, который ты изменил.

## researcher не пишет в базу знаний

- Запись исследователю разрешает guard-хук, и только в `docs/dp/knowledge/*.md`. Если путь
  базы другой (переменная `DP_KB_DIR`), она должна быть одинаковой для всех хуков.
- В plan mode Opus иногда сам не решается звать пишущего сабагента. Правила это прямо
  разрешают; можно сказать явно: «спроси researcher».

## setup сообщил `! model is …`

В настройках уже стоит другое значение, и `setup` его не трогает. Если хочешь значение
плагина, запусти `/dev-pattern:uninstall` (база знаний останется), потом `/dev-pattern:setup`
и согласись на перезапись. Если нет — оставь как есть, всё остальное работает.

## Вернуть всё как было

`/dev-pattern:uninstall`. Если `settings.json` после установки не правили, он восстановится
байт в байт; иначе удалятся только ключи плагина, причём только те, что ещё хранят значение
плагина. `--purge-kb` удаляет и `docs/dp/`.
