# dev-pattern

Плагин для Claude Code, который делает работу **экономной по токенам, предсказуемой и
понятной**:

- **База знаний.** Всё, что выяснено о коде, записывается в `docs/dp/knowledge/` с индексом.
  В следующий раз Claude не исследует заново, а читает нужный модуль.
- **Исследование на дешёвой модели.** Читает код сабагент `researcher` на Sonnet. Он сам
  обновляет базу знаний и отдаёт Opus короткую выжимку.
- **План перед любой работой.** Каждая сессия начинается в plan mode: ты видишь, что будет
  сделано, и одобряешь это до первой правки.
- **Документация не отстаёт.** Если код изменился, а документация нет, Stop-хук не даёт
  закончить ход, пока Claude не обновит документы или явно не объяснит, почему они не нужны.
- **Режим учителя.** Стили `tutor` и `tutor-practice` превращают сессию в туториал. Claude
  объясняет, что сделал, почему так и какие были альтернативы, а во втором стиле ещё и даёт
  тебе написать кусок кода самому.

Плагин ставится в существующий репозиторий и ничего там не ломает: он не трогает
`CLAUDE.md`, код и CI, дописывает только свои ключи в настройки и откатывается одной
командой до исходного состояния байт в байт.

## Установка

В Claude Code:

```
/plugin marketplace add avehun/dev-pattern
/plugin install dev-pattern --marketplace avehun/dev-pattern
```

Потом в нужном репозитории:

```
/dev-pattern:setup
```

`setup` спросит режим:

| | `shared` — для команды | `local` — только для меня |
| --- | --- | --- |
| Настройки | `.claude/settings.json` | `.claude/settings.local.json` |
| `docs/dp/` | коммитится | скрыт через `.git/info/exclude` |
| Коллеги | получают тот же процесс | ничего не замечают |

Что именно меняется, видно заранее (`dp-setup --dry-run`). Если в настройках уже есть
ключ с другим значением, например `model`, `setup` его не трогает, пока ты не разрешишь.
После установки открой новую сессию.

Удалить: `/dev-pattern:uninstall`. Если настройки после установки никто не правил, они
вернутся байт в байт; иначе удаляются только ключи плагина. База знаний по умолчанию
остаётся.

## Как выглядит сессия

```
ты: «добавь экспорт отчёта в CSV»
 │
 ├─ старт: хук подставляет правила и индекс базы знаний
 ├─ plan mode: Opus смотрит индекс → researcher (Sonnet) дочитывает код, пишет в базу
 ├─ план: цель, шаги, файлы, риски, какие документы обновятся → ты одобряешь
 ├─ работа: Opus пишет код (механику может отдать worker на Sonnet) → проверяет
 └─ финиш: документация и база знаний обновлены — иначе Stop-хук не отпустит
```

Режим учителя: `/output-style dev-pattern:tutor` или `/output-style dev-pattern:tutor-practice`.

## Структура репозитория

```
.claude-plugin/marketplace.json   репозиторий — маркетплейс с одним плагином
plugins/dev-pattern/              сам плагин
  agents/          researcher, worker (Sonnet)
  hooks/           SessionStart, PreToolUse (guard), Stop
  scripts/         код хуков и общая библиотека
  bin/             dp-setup, dp-uninstall, dp-kb-stale, dp-docs-waive (в PATH у Claude)
  skills/          setup, uninstall, knowledge
  output-styles/   tutor, tutor-practice
  templates/       индекс и модуль базы знаний
  rules.md         правила, которые хук подставляет в каждую сессию
docs/              эта документация
scripts/check.sh   самопроверка репозитория
```

Зависимости: `bash`, `git` (2.31+), `jq`, `awk`, `sed`.
