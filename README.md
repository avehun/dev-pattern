# dev-pattern

Универсальный процесс ИИ-разработки с разделением ролей:
**оба агента — Claude Code, лид на Opus, исполнитель на Sonnet.**

Репозиторий даёт готовый комплект: структуру документации, набор спек-артефактов,
инструкции для обеих ролей, хук с жёсткими границами прав и скрипты для передачи задач.
Раскатывается в любой проект одной командой — без второго инструмента, без отдельного
логина, без отдельной оплаты.

Дальше команд нет. Вы говорите словами, что нужно сделать; лид сам заполняет документы
проекта, разбивает работу на задачи, вызывает исполнителя, ревьюит результат и принимает его.

```
                      вы: «надо, чтобы сессии переживали рестарт»
                        │
        ┌───────────────▼──────────── Claude Code, лид (Opus) ──────────────────────┐
        │  онбординг → исследование → спека → план → декомпозиция → РЕВЬЮ → приёмка │
        └───────────────┬───────────────────────────────────────▲──────────────────┘
                        │ карточка задачи T-XXX.md              │ diff + отчёт
                        ▼                                       │
        ┌──────────────── Claude Code, исполнитель (Sonnet) ────┴──────────────────┐
        │  читает карточку → пишет код и тесты → гоняет verify → пишет отчёт       │
        └──────────────────────────────────────────────────────────────────────────┘
```

## Зачем это

Дорогая модель хорошо думает, но тратить её на рутинный код по готовой постановке
расточительно. Разделение работает, если **вся сложность вынесена в постановку задачи**:
лид делает исследование и принимает решения, а исполнитель получает точную карточку с
указателями на нужный код, из которой невозможно уйти в сторону.

Границы здесь не только на словах. Проектный хук (`.claude/hooks/dp-guard.sh`) **на уровне
вызова инструмента** блокирует исполнителю запись в `docs/`, `CLAUDE.md`, `.claude/` и
любой git — так что «случайно переписать спеку» он не может физически, независимо от того,
что написано в промпте.

Автономия лида ограничена так же явно. Уровень задаётся в `docs/constitution.md`, и ни на
одном из них лид не решает за вас, что считать готовым: критерии приёмки вы подтверждаете
всегда, а на миграциях, авторизации, платежах, удалении данных и новых зависимостях он
останавливается независимо от настроек. `git push` вне зависимости от автономии остаётся
под запретом.

Третье — постоянная память проекта (`docs/knowledge/`): всё, что лид изучил про кодовую
базу, фиксируется с индексом, чтобы следующая фича не переисследовала то же самое с нуля.
См. [База знаний](docs/knowledge-base.md).

## Быстрый старт

```bash
git clone https://github.com/avehun/dev-pattern.git ~/dev-pattern

cd /путь/к/вашему/проекту
bash ~/dev-pattern/scripts/init.sh .
```

Это единственная команда, которую вы запускаете руками. Дальше открываете Claude Code в
этой папке и говорите словами, что нужно сделать:

```
$ claude
> надо, чтобы сессии переживали рестарт сервера
```

Лид увидит, что проект ещё не онбординжен, прочитает манифесты, конфиги и CI, **запустит
каждую найденную команду** — чтобы не записать в конституцию неработающий гейт, — спросит
пачкой то, чего нет в репозитории, и заполнит `docs/constitution.md`, `docs/stack.md`,
`docs/architecture.md`, `docs/glossary.md` и первые записи `docs/knowledge/`. После этого
возьмётся за саму фичу: исследование, спека, план, декомпозиция, делегирование, ревью,
приёмка. Команды при этом гоняет он, не вы.

Отдельной установки или логина для исполнителя не нужно — это тот же Claude Code, тот же
аккаунт, просто другая модель для другой роли (см. [Настройка моделей](docs/models.md)).

### Где вы всё-таки нужны

`docs/constitution.md` задаёт уровень автономии, от него зависят остановки:

| `autonomy` | Лид останавливается |
| --- | --- |
| `manual` | на каждом шаге: печатает команду, запускаете вы |
| `supervised` (по умолчанию) | подтверждение критериев приёмки → эскалация задачи → финальный quickstart |
| `auto` | только подтверждение критериев приёмки |

На **любом** уровне лид останавливается безусловно, когда упал quality gate и починка
неочевидна, когда правка задевает миграции, авторизацию, платежи или удаление данных, когда
нужна новая зависимость и когда просьба противоречит конституции.

### Команды, если вести процесс руками

```
/dp:onboard                          → заполнить документы проекта (--recheck — сверить)
/dp:feature кэш сессий               → весь цикл разом
/dp:research кэширование токенов     → docs/specs/…/research.md
/dp:spec token-refresh               → docs/specs/001-token-refresh/spec.md
/dp:plan                             → plan.md, data-model.md, contracts/
/dp:tasks                            → tasks.md + tasks/T-001.md …
/dp:delegate T-001                   → исполнитель пишет код, отчёт в reports/
/dp:review T-001                     → reviews/T-001.md + вердикт
/dp:accept T-001                     → гейты, коммит, обновление доков
```

## Что устанавливается в проект

| Файл | Кому | Роль |
| --- | --- | --- |
| `CLAUDE.md` | лид | роль тимлида, маршрутизация запросов, точки остановки, правила ревью |
| `.claude/settings.json` | лид | модель (opus), права, хук, git для приёмки без лишних вопросов |
| `.claude/agents/dp-*.md` | исполнитель | `dp-implementer`, `dp-fixer`, `dp-test-writer` — все на sonnet |
| `.claude/hooks/dp-guard.sh` | оба | **принудительные** границы прав исполнителя на файлы и bash |
| `.claude/commands/dp/*` | лид | 10 слэш-команд процесса, включая `onboard` и `feature` |
| `docs/constitution.md` | оба | quality gates, уровень автономии, запреты — выше всех остальных инструкций |
| `docs/knowledge/` | оба | постоянная память проекта — лид пишет, оба читают |
| `docs/.templates/*` | лид | шаблоны всех спек-артефактов |
| `scripts/*` | лид | `prepare-delegation.sh`, `set-status.sh`, `new-feature.sh`, `doctor.sh`, `status.sh` |
